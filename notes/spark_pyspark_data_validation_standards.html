Spark / PySpark Data Validation Notes

Last Updated: Sep 2025
Spark PySpark Hive ClickHouse Data Quality

1. Background

This note documents a production-level Spark / PySpark data validation pipeline used to verify consistency between source and target data systems.

Typical use cases include:

  • Hive → ClickHouse data validation
  • Hive → MongoDB data validation
  • Incremental backfill and data quality monitoring

2. High-Level Pipeline

  1. Load task configuration (JSON-based)
  2. Read source data from Hive
  3. Read target data (ClickHouse / MongoDB)
  4. Normalize schema and data types
  5. Compute row-level MD5 hash
  6. Detect missing and mismatched records
  7. Write backfill / exception data
  8. Report validation results to monitoring system

3. Data Normalization Standards

To ensure deterministic and reproducible hash results, all fields involved in MD5 computation must follow strict normalization rules.

3.1 Null Handling

  • All null values are converted to empty strings ""
  • No literal string "null" is allowed

3.2 String Fields

  • Trim leading and trailing whitespace
  • Optional lowercasing if case-insensitive
  • UTF-8 encoding enforced

3.3 Numeric Fields

  • Decimals normalized to fixed scale
  • 1 and 1.0 must produce identical hash input

3.4 Date & Timestamp

  • Unified timezone (UTC)
  • Formatted as yyyy-MM-dd HH:mm:ss

4. MD5 Hashing Convention

MD5 is computed on a canonical string constructed from ordered fields.

field_1 || '|' || field_2 || '|' || field_3 || ...
  • Field order must be explicitly defined
  • Delimiter must not appear in raw field values

5. Join Strategy & Missing Record Detection

Inner joins may cause silent data loss when join keys are missing. Therefore, missing records are detected explicitly.

  • Source-only records → backfill candidates
  • Target-only records → data drift indicators
  • Joined records → eligible for MD5 comparison

6. Performance Considerations

  • Avoid accidental broadcast joins on large datasets
  • Detect and mitigate data skew on join keys
  • Unpersist cached DataFrames aggressively
  • Prefer built-in Spark SQL functions over UDFs

7. Output & Reporting

  • Backfill data written to Hive partitioned tables
  • Mismatch records stored for auditing
  • Validation metrics reported to monitoring system

8. Summary

This pipeline emphasizes correctness, reproducibility, and operational visibility. Strict normalization and well-defined standards are essential for reliable cross-system data validation.

In short: normalize everything deterministically, hash with a canonical field order, detect missing records explicitly, and surface results quickly for monitoring and backfill.
